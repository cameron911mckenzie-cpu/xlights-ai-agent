# xLights integration reference

How **xlights-ai-agent** plugs into xLights, and where each contract comes from
in the xLights source tree
([xLightsSequencer/xLights](https://github.com/xLightsSequencer/xLights), GPLv3).

## 1. AI plugin DLLs (`ai_plugins/`)

xLights has a C ABI for third-party AI services:

* **Headers**: `src-core/ai/aiPlugin.h`, `aiBase.h`, `aiType.h`,
  `ServiceProperty.h`, `IServiceSettingsStore.h` — all vendored verbatim under
  `ai_plugins/AIAutoSequencer/third_party/xlights/`.
* **Discovery**: `ServiceManager::loadPlugins(pluginDir)` scans the
  `ai_plugins/` directory **next to the xLights executable** for `.dll` / `.so` /
  `.dylib` files and loads the ones exporting both entry points
  (`src-core/ai/ServiceManager.cpp`, wired up in
  `src-ui-wx/xLightsMain.cpp`).
* **Entry points** (generated by the `XL_AI_PLUGIN_EXPORT(ClassName)` macro):

  ```cpp
  extern "C" aiBase* xlCreateAIService(ServiceManager* sm);
  extern "C" void    xlDestroyAIService(aiBase* service);
  ```

  Memory is freed through the DLL's own destroy function, and `aiBase` is fully
  inline so plugin DLLs need **no linkage back into the xLights binary**.
* **Capabilities** (`aiType::TYPE`): `PROMPT`, `COLORPALETTES`, `IMAGES`,
  `MAPPING`, `SPEECH2TEXT`. The host UI surfaces them in
  *Preferences → Services*, the AI colour-palette dialog, etc. The addon service
  advertises `PROMPT` + `COLORPALETTES`.
* **Settings**: `GetProperties()` returns declarative `ServiceProperty` rows
  (Category/Bool/String/Secret/Int/Choice) which the host renders in a
  property grid. Ids are dot-qualified and must start with the service name
  returned by `GetLLMName()` — here `AIAutoSequencer.*`.
* **Lifecycle**: `LoadSettings()` runs when the service is registered;
  `SaveSettings()` persists. The addon keeps its conf file in the user config
  dir (`~/.config/xlights-ai-agent/AIAutoSequencer.conf`, `%APPDATA%` on
  Windows) because `ServiceManager`'s settings store is not reachable from a
  plugin (its methods are non-inline).

There is **no sequencing hook** in this ABI — it covers prompts, palettes,
images, mapping and lyrics. Beat-accurate sequencing therefore rides on the
automation API below, which is exactly what xLights' own MCP server exposes for
AI agents.

## 2. REST automation API

Enabled by the xFade/automation preference; ports **49913** (instance A) and
**49914** (instance B). Reference: `documentation/xlDo Commands.txt`,
dispatcher in `src-ui-wx/automation/xLightsAutomations.cpp`.

| Call | Purpose in this addon |
|---|---|
| `GET /getVersion` | port discovery (`xlights-ai status`) |
| `POST /xlDoAutomation {"cmd": ...}` | all commands below |
| `getModels` | model + group names to plan against |
| `getOpenSequence` | duration / frame size / open sequence state |
| `newSequence` | create a sequence for a media file (`--new-sequence`) |
| `addEffect` | push one placement: `target`, `effect`, `startTime`, `endTime`, `layer`, `settings`, `palette` |
| `clearModelEffects` | `--replace`: clear a model before pushing |
| `renderAll` / `saveSequence` | `--render` / `--save` |

`settings`/`palette` may be sent as JSON **objects** (the MCP bridge stringifies
them) or as JSON **strings** — the handler detects a leading `{` and runs both
through the same JSON setters (`xLightsAutomations.cpp`, `addEffect` branch).
The addon sends JSON strings over REST and objects over MCP.

Palette keys are xLights' 8 colour buttons:
`C_BUTTON_Palette1..8` + `C_CHECKBOX_Palette1..8`. Effect setting keys match
what each effect's render code reads (`Marquee_Speed`, `Twinkle_Count`,
`CHOICE_Butterfly_Colors`, `SLIDER_Garlands_Type`, …), verified against
`src-core/effects/*Effect.cpp`.

## 3. MCP endpoint

`POST /mcp` on the same port speaks JSON-RPC 2.0 (stateless Streamable HTTP),
see `src-ui-wx/automation/xLightsMCPServer.cpp`.

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"addEffect","arguments":{
   "target":"MegaTree","effect":"Butterfly",
   "startTime":"8000","endTime":"8500","layer":"0",
   "settings":{"Butterfly_Speed":"35"},
   "palette":{"C_BUTTON_Palette1":"#FF1A1A","C_CHECKBOX_Palette1":"1"}}}}
```

Tools: `xlights_command` (generic, every command from xlDo), `getVersion`,
`getOpenSequence`, `openSequence`, `saveSequence`, `closeSequence`, `renderAll`,
`getModels`, `getControllers`, `getEffectSettings`, `setEffectSettings`,
`addEffect`, `deleteEffect`, `lightsOn`, `lightsOff`.

```bash
xlights-ai sequence song.mp3 --prompt "..." --transport mcp
```

## 4. Beat files (`*_beats.txt`)

xLights/VAMP beat files are whitespace-separated rows:

```
0.081270	0.081270	2
0.499229	0.499229	3
0.870748	0.870748	1
```

i.e. `start_seconds  end_seconds  beat_in_bar` (1 = downbeat). The addon
imports them (`--beats`) and exports them (`analyze --beats-out`) in exactly
this format, so analysis can be shared with xLights' own beat timing track.

## 5. Data flow

```
 song.mp3 ──▶ beat engine ──▶ style engine ──▶ planner ──▶ xlights_client
                (BPM,         (prompt →        (beat-      (REST /xlDoAutomation
                 sections)     style+palette)   cadence     or MCP /mcp, ports
                                                 effects)    49913/49914)
                                                                 │
   ┌── xLights ──────────────────────────────────────────────────┴───────────┐
   │  addEffect / clearModelEffects / renderAll / saveSequence              │
   │                                                                         │
   │  Preferences → Services ── AI Auto Sequencer (ai_plugins DLL)          │
   │        PROMPT / COLORPALETTES requests                                  │
   │                 │ HTTP                                                  │
   └─────────────────┼───────────────────────────────────────────────────────┘
                     ▼
          xlights-ai serve  (local agent, 127.0.0.1:8756)
          /v1/prompt  /v1/palette  /v1/analyze  /v1/plan  /v1/sequence
```

The plugin DLL is the in-app surface (prompts & palettes inside xLights); the
CLI/agent does the heavy sequencing through the automation API. Both share the
same style engine, so what the palette dialog suggests is what the sequence gets.
